# Исправления клиента 0.1.5

Повторная проверка 8 ноября 2026 года после реального воспроизведения на 0.1.4.
Предыдущая правка не закрывала все причины. Свежая сборка использует протокол 5; обновить нужно обе стороны.

## Рывок и смена оружия

У клиента счётчики `Sent input: Dash / Switch` оставались на `1`, несмотря на повторные нажатия.
Это локализует проблему до сетевой отправки: повторные события не попадали в клиентский PadState.
Отсутствие настроенных привязок не объясняет предоставленное наблюдение, когда до подключения кнопки работают.

В 0.1.5 ввод снимается в `ReInput.UpdateEndedEvent` для цикла Update и сохраняется до отправки в LateUpdate.
Повторный опрос в том же кадре не увеличивает счётчик второй раз. Начало сессии и переподключение сбрасывают
локальный кэш, удержания и счётчики. Сохраняется резервное распознавание нажатия по переходу удержания.

Дополнительно остановлен `PlayerManager.Update` на зеркальном клиенте: постоянный CupheadCore продолжал
выполнять логику локального присоединения/переподключения устройств, хотя сцена уже была заморожена.
Назначенный контроллер сохраняется. Если клиент подключился с титульного экрана до назначения геймпада,
подхватывается тот свободный контроллер, на котором нажата кнопка, с загрузкой его сохранённых привязок.
`PauseManager.Unpause` больше не может включить замороженные игровые компоненты через их `preEnabled`.

Граница подтверждения: сетевой путь проверен в настоящей игре со скриптовым клиентским PadState.
Опрос реальной клавиатуры/геймпада друга после подключения должен быть подтверждён на его компьютере.
Неподвижные счётчики `1 / 1` были получены на 0.1.4; не следует считать тест скриптового ввода доказательством
исправления любого драйвера или реального устройства.

## Исчезающие и повреждённые надписи

Найдены дополнительные причины, которых не устраняла замена шрифта/материала в 0.1.4:

1. **Масштаб облачков NPC.** Мод выбирал камеру для WorldSpace Canvas по позиции его корня. Это мог быть
   UICamera с большим ортографическим размером, а не камера карты. В результате реплика уменьшалась до
   нескольких пикселей. Теперь используется камера, явно назначенная игрой в `canvas.worldCamera`;
   поиск другой камеры применяется только при её отсутствии/непригодности.
2. **Каналы вершин TMP.** У создаваемого зеркального Canvas не включался TexCoord1, а старая встроенная в игру
   версия TMP не добавляет его сама. Включены TexCoord1, Normal и Tangent. TMP получает необходимые данные
   для SDF-отрисовки букв. Назначение каналов описано в
   [документации Unity](https://docs.unity.com/en-us/engine/6000.5/script-reference/unityengine/canvas/additionalshaderchannels).
3. **Длинные реплики.** `SpeechBubble.GetNormalizedText` расширяет пробелы тегами вроде `<space=11.19853>`.
   Получившийся UI-элемент может превысить MTU. Исходный код полностью пропускал такую запись. Теперь она
   передаётся надёжными фрагментами и собирается до применения. Размер одной записи ограничен 64 KiB,
   число незавершённых записей — 64, состояние очищается при смене сцены/соединения.
4. **Разный порядок доставки.** Версии полей UI отслеживаются отдельно. Более свежая координата больше
   не заставляет отбросить поздно пришедший текст целиком. Старый текст при этом не перезаписывает новый.
5. **Поздний атлас шрифта.** TMP-ресурс без атласа/материала считается ещё не готовым; после загрузки
   выполняются повторная привязка и обновление шрифта.

## Выполненные проверки

- Сборка Release на DLL из `F:\Games\Cuphead\Cuphead_Data\Managed`: без предупреждений и ошибок.
- HookCheck: 16 целей Harmony и 18 отражаемых членов присутствуют; 3 поиска с динамическим типом вне проверки.
- SyncCheck: 36 проверок, включая опрос в событии Rewired, сброс сессии, физические края, фрагментацию
  длинной кириллической строки, перестановку датаграмм и независимые версии полей.
- Две настоящие копии игры, прямой UDP на localhost. Отдельные копии EXE/BepInEx/плагина и логов;
  `CUPHEAD_ONLINE_TEST_READONLY=1` запрещал `PlayerData.SaveCurrentFile`. Только данные игры использовались
  через junction. Тестовые процессы завершены; установленный плагин пользователя не заменялся.
- В тестовом бою получены **12/12 физических событий рывка и 12/12 смен оружия**. В логах подтверждены
  `p2 ... dash=Dashing` и переключение `p2 ... weapon=level_weapon_spreadshot`.
  Тест использовал команды `invincible` и `keeprunning`, чтобы смерть/запрос контроллера в тестовом окне
  не прерывали проверку. Клиентские действия задавались через TestDriver, проходили настоящую сеть и физику.
- На обеих сторонах визуально проверены длинная русская реплика в настоящем WorldSpace-облачке карты и
  карточка смерти дракона с русской цитатой. Текст у клиента полностью читается. Для изоляции проверки
  использованы тестовые команды `dialog` и `gameover`, а не прохождение боя до смерти.

Скриншоты клиента сохранены в `dist/0.1.5/verification/`; краткие доказательства из лога — в
`dist/0.1.5/verification/input-check.txt`. Это результаты тестовых экземпляров, не диагностика устройства друга.

Для повторения модульных проверок:

```powershell
dotnet build -c Release -p:GameManaged=F:/Games/Cuphead/Cuphead_Data/Managed
dotnet run --project tools/SyncCheck/SyncCheck.csproj -c Release
```

После замены DLL на обоих компьютерах требуется полностью перезапустить обе игры. У клиента в F8 счётчики
Dash/Switch должны увеличиваться при новых нажатиях. Если они снова стоят на месте, нужен уже лог клиента
с 0.1.5 — имеющиеся данные 0.1.4 не позволяют проверить работу нового обработчика на его устройстве.

Самостоятельный локальный интерфейс переназначения кнопок во время соединения этой правкой не добавлен.
